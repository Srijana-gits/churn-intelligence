# Churn Intelligence dashboard

Open [churn_intelligence.twbx](churn_intelligence.twbx) in Tableau Public or Tableau
Desktop. It embeds its data and requires no server connection. The adjacent `.twb`
uses the extracts in `data/`. Rebuild the extracts after changing the CSVs.

[View the published interactive dashboard on Tableau Public](https://public.tableau.com/app/profile/srijana.shrestha8012/viz/churn_intelligence/Customerpriorities)

The workbook is generated by `python src/build_tableau.py` using
[Tableau's official Hyper API](https://tableau.github.io/hyper-db/docs/guides/hyper_file/create_update/).
It includes four Hyper extracts for compatibility with Tableau Public. Extract
row counts, XML sheet references, connections, and embedded data are checked.
Tableau loaded the extract-backed workbook and rendered its initial worksheet
during verification. Full visual and filter validation still needs a desktop
review; macOS denied interface-text access and no capturable Tableau window was
available to the screenshot helper.

## Views

1. **Overview:** customer count, observed churn, monthly billing, and churn by
   contract, internet service, and payment method. Uses all 7,043 customers.
2. **Model performance:** contact-capacity recall and precision, plus calibration
   on the fixed 1,758-row held-out sample. The header reports ROC-AUC, average
   precision, and Brier score. These results are distinct from the full-population
   exploratory ranking comparison.
3. **Customer priorities:** counts and score × monthly bill by bucket, a score/bill
   scatterplot, and a ranked contact table. The bucket, contract, and internet
   filters apply to the contact table only; the summary charts provide context
   for the complete eligible current population. The table shows the persisted
   global rank, which does not reset when filtered. Scroll to view more customers.

## Data contract

| File | Population / meaning |
|---|---|
| `data/customers_scored.csv` | All 7,043 customers, original service categories, observed churn, and scoring eligibility |
| `data/priority_list.csv` | 5,163 eligible current customers, ranked by score × monthly bill |
| `data/bucket_summary.csv` | Counts and share of the ranking measure by priority bucket |
| `data/capacity_metrics.csv` | Held-out precision and recall for the top 10%, 20%, and 30% |
| `data/calibration.csv` | Held-out observed churn versus predicted score, by score decile |
| `data/model_metrics.csv` | Held-out ROC-AUC, average precision, Brier score, and baseline Brier score |
| `data/ranking_comparison.csv` | Exploratory policy comparison using full-population OOF scores |
| `data/metadata.json` | Population counts, exact cutoffs, scoring method, and cleaned-data fingerprint |

The 11 zero-tenure customers have blank scores, `model_eligible=false`, and
`scoring_status="Excluded: zero tenure"`. Blank means unscored, not zero risk.
They are included in descriptive totals but excluded from priorities. Of 5,174
customers labelled current in the snapshot, 5,163 are eligible for scoring.

Dashboard scores use `retrospective_5_fold_oof`: each eligible customer is scored
by a model that did not fit that customer's row. Model selection nevertheless
reused this dataset, so the policy comparison is exploratory. New-customer scoring
uses a separate full-data model and the method `full_data_fitted_model`; it does
not replace these retrospective dashboard exports.

The exact cutoff is `0.31871380378169745`, selected by maximising F1 on training
OOF predictions, and the high-bill cutoff is `$64.45`. Equality belongs in the
high-risk or high-bill group. Ranking uses unrounded score × bill, then customer
ID to break ties. Scores are exported with 12 significant digits; display
rounding must not be used to recompute bucket membership.

**Score × monthly bill is a ranking measure.** It is not expected losses, profit,
or savings. Scores describe similarity to churners in a historical snapshot;
they do not establish who will leave next month or whether an offer will work.

## Refresh and validate

From the repository root, with the raw file in `data/raw/`:

```bash
python src/run_pipeline.py
python -m unittest discover -s tests -v
```

Reopen the regenerated `.twbx` to load its newly embedded CSVs. An already-open
package has its own embedded copy; refreshing it does not import a newly built
package. The adjacent `.twb` also reads the rebuilt local Hyper extracts.

Desktop review should confirm the three dashboard tabs, the overview count
(7,043), observed churn (26.54%), the bucket counts (835 / 280 / 1,750 / 2,298),
and contact-table filters. Save an overview screenshot to
`reports/figures/dashboard_overview.png` after confirming the render.

Publishing is a separate action. The local workbook is not published online.
